# Security policy

## Reporting

Do not disclose a suspected vulnerability in a public issue. Until a private security contact is published, use the repository host's private vulnerability-reporting feature. The project must establish a monitored security address before public launch.

Include affected version or commit, impact, reproduction steps, and any suggested mitigation. Do not access other users' data, exhaust shared resources, or test production without authorization.

## Supported versions

No production release exists in Phase 0. Security fixes will target the default branch until a release policy is established.

## Response expectations

Maintainers will acknowledge reports when the private reporting channel becomes operational, assess severity, coordinate remediation and disclosure, and credit reporters who wish to be named. No response-time SLA is promised before the security function is staffed.

The system threat model is maintained in [docs/engineering/security.md](docs/engineering/security.md).
